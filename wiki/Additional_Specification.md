# Дополнительная спецификация: Безопасность, Надежность и Эргономика (GitHub Wiki)

> Уточнение ЛР4: HMAC требует секретного ключа; проверка по открытой соли некорректна. Для независимой офлайн-проверки целевая схема использует асимметричную подпись. Между отключенными сканерами повтор обнаруживается только при синхронизации. [Контракт и ограничения MVP](../docs/reports/Lab4_report.md).

> **Статус документа:** Предварительная спецификация целевых нефункциональных требований (Target NFR), криптографического протокола и эргономических стандартов доступности для последующих этапов проектирования и разработки (Лабораторные работы №2–8).

Настоящая спецификация устанавливает комплекс нефункциональных требований (NFR) к экосистеме **CampusMeet**, регламентирует архитектуру криптографической защиты офлайн-билетов, протокол предотвращения повторных проходов и стандарты цифровой доступности.

---

## 1. Требования к надежности и производительности (KPIs)

* **NFR-PERF-01 (Скорость оптического чекина):** Время от наведения объектива камеры сканера на экран участника до отображения визуального вердикта (*«Вход разрешен»*) не должно превышать **500 миллисекунд** в 95% случаев.
* **NFR-PERF-02 (Время холодного старта билета):** Вызов экрана с персональным QR-билетом из заблокированного состояния смартфона должен осуществляться за время менее **1.5 секунд** при отсутствии интернет-соединения.
* **NFR-REL-01 (Отказоустойчивость Offline-First):** Все ключевые функции участника (предъявление билета, навигация по сохраненному расписанию) должны быть на 100% работоспособны при полном отключении Wi-Fi и сотовой связи на площадке.
* **NFR-REL-02 (Целостность данных при синхронизации):** Очередь чекинов, совершенных сканером волонтера в автономном режиме, должна гарантированно отправляться на сервер при восстановлении соединения с разрешением коллизий по правилу *First-Timestamp Wins*.
* **NFR-SCALE-01 (Нагрузочная способность на старте регистрации):** Веб-сервер и очередь заявок должны выдерживать пиковую нагрузку до **100 запросов в секунду (RPS)** в момент открытия регистрации на популярные хакатоны.

## 2. Протокол офлайн-билета с динамической криптографической верификацией (HMAC-SHA256)

Для исключения мошенничества (подделки QR-кодов, пересылки скриншотов чужих билетов) и одновременного обеспечения мгновенного открытия билета без обращения к серверу разработан криптографический протокол CampusMeet Offline Pass.

### 2.1. Структура полезной нагрузки QR-кода (QR Payload)
Полезная нагрузка представляет собой компактную Base64URL-кодированную строку, состоящую из заголовка, тела и криптографической подписи:

$$\text{Payload} = \text{Base64URL}(\text{Header}) \,.\, \text{Base64URL}(\text{Claims}) \,.\, \text{HMAC-SHA256}(\text{Header} \,.\, \text{Claims}, K_{event})$$

Где блок `Claims` содержит следующие поля:
```json
{
  "tid": "CMP-2026-X89K",         // Уникальный публичный код билета
  "eid": "ev-campusmeet-2026",    // Идентификатор события
  "uid": "usr-artem-001",         // Идентификатор пользователя
  "typ": "std",                   // Тип билета (std = standard, spk = speaker, vol = volunteer)
  "iat": 1759240800,              // Timestamp выдачи билета
  "exp": 1759327200,              // Timestamp окончания валидности
  "seq": 1                        // Ревизия билета (для аннулирования при перевыпуске)
}
```

### 2.2. Механизм офлайн-валидации сканером
1. Перед началом смены на стойке регистрации мобильное приложение волонтера загружает и сохраняет в защищенном хранилище (SecureStore) симметричный ключ проверки события $K_{event}$ и реестр отозванных билетов (Revocation List).
2. При считывании кода сканер вычисляет HMAC-подпись от полученных `Header.Claims` и выполняет проверку подлинности подписи в QR-коде локально без сетевых запросов.
3. Сканер проверяет локальный журнал `check_in_logs`:
   * Если билет не встречался ранее — фиксируется факт прохода, выводится зеленый экран и подается вибросигнал успеха.
   * Если билет уже был отсканирован — выводится предупреждающий экран с точным временем первой фиксации и именем волонтера, оформившего проход.

## 3. Защита от злоупотреблений и анти-персонажей (Anti-Fraud Policy)

В исследовании пользователей выделен отрицательный персонаж (Влад, «мерч-хантер»), регистрирующийся на все события ради бесплатных угощений и сувениров, блокирующий квоты мест и не приходящий на доклады (No-Show).

Для защиты организаторов внедрен трехуровневый контур:
1. **Динамический дедлайн подтверждения (RSVP Re-confirmation):** За 24 часа до старта мероприятия пользователю направляется Push/Telegram-запрос на подтверждение присутствия. Если подтверждение не получено за 6 часов до начала, бронь аннулируется, а билет передается первому участнику из листа ожидания (Waitlist).
2. **Индекс надежности участника (Attendance Score):** Пользователи с систематическими пропусками (более 2 неявок подряд без заблаговременной отмены) понижаются в приоритете получения мест на закрытые хакатоны и воркшопы.
3. **Hard-Cap & Replay Protection:** Запрет множественной регистрации одного физического лица на одно мероприятие по одинаковым контактам Telegram / телефону.

## 4. Эргономика моторики и цифровая доступность (Accessibility / WCAG 2.1 AA)

* **Эргономическая зона Thumb Zone:** Все интерактивные триггеры быстрого действия (кнопка развертывания билета, кнопка активации сканера, переключение табов программы) расположены в нижней трети экрана смартфонов (в пределах естественного радиуса движения большого пальца руки).
* **Контрастность интерфейса:** Минимальный коэффициент контрастности текста и ключевых пиктограмм составляет не менее **4.5:1** (соответствие стандарту WCAG 2.1 Level AA).
* **Адаптация к внешнему освещению:**
  * Режим *Auto-Max Brightness* при выводе QR-кода на улице в солнечную погоду.
  * Высококонтрастная темная тема (*OLED Dark Theme*) для лекционных залов с выключенным светом, исключающая ослепление сидящих рядом слушателей.
* **Мультисенсорное дублирование:** Каждый статус верификации (успех / отказ / повтор) дублируется тремя независимыми каналами восприятия: цветом, контрастной иконкой/надписью и уникальным вибротактильным паттерном Haptic.
